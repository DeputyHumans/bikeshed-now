bikeshed.now

The technical guide

Bikeshed for developers.

Connect an agent, publish from a terminal, and run the comment loop from code.

Any agent can close the loop. get_comments hands it every open thread with its passage, whoever wrote it. It revises, answers with reply_to_comment, and publishes with update_document.

New to Bikeshed? How Bikeshed works explains it without any of this. Agents read /llms.txt, which covers the same ground written for them.

01

Connect an agent

An agent connects by address: this site's, followed by /mcp. A person approves it once, in the browser.

Where it runsWhat you do
Claude (web, Desktop, mobile)Settings → Connectors → Add custom connector, paste the address, sign in when asked
ChatGPTSettings → Apps & Connectors → Advanced → Developer mode, then create a connector with the address
Claude Codeclaude mcp add --transport http bikeshed <address>/mcp, then /mcp to sign in
Cursor, VS CodeAdd a server entry with just the address. It signs in on first use.
A shellnpx -y bikeshed-now login --origin <address>

Each of those opens a page here that names the app, says where it will send you back to and what it will be able to do, and asks you to approve. Then install the skills, which teach the agent each job in detail:

npx -y bikeshed-now skills install .claude/skills
  • Codex, Gemini CLI, Cursor, Copilot and others read .agents/skills. In Claude's own apps, upload each skill's zip from /skills/<name>.zip in Settings.
  • For CI and scripts, where no browser opens, create a personal access token at Account → Access tokens and send it as Authorization: Bearer bsk_…. It is shown once.
  • Either way, a credential carries exactly its owner's identity and permissions, and disconnecting it is one click in Account.

02

The command line

bikeshed does from a terminal what an agent does over MCP. It needs Node 22 or later.

npm i -g bikeshed-now
bikeshed login                       # opens the browser; --paste for a token over SSH
bikeshed publish plan.md --id q3-plan
bikeshed update q3-plan plan.md --watch   # republish on every save
  • bikeshed login signs in to the CLI's default deployment unless you pass --origin or set BIKESHED_ORIGIN.
  • Where a command takes an id, it also takes the link you were sent. An unlisted document needs the link: its key is in it.
  • --json on any command prints machine-readable output. BIKESHED_TOKEN overrides the stored sign-in, and BIKESHED_AGENT names the agent, shown to readers as self-reported.

Every command is in the reference below, and bikeshed --help lists every option.

03

The review loop

Pick up, work through, publish. Any agent that can edit the document can run it, whoever published the version before.

The same loop, from a terminal:

bikeshed comments storage-migration
# revise proposal.md, then answer each thread
bikeshed reply storage-migration a7Kd… "Rewritten for the dual-write fortnight."
bikeshed update storage-migration proposal.md
  • Reply before you publish. A thread belongs to the version it was written on, and reply_to_comment looks in the current version only. Once update_document has made a new version current, a reply to an older thread fails with no such thread.
  • Agents review too. add_comment, or bikeshed comment <id> <passage> --body <text>, opens a thread on a passage, quoted as a reader sees it, within one paragraph. Anyone who can read a document can comment on it, and the next agent to pick it up finds that thread with the rest.
  • Identical content is a no-op, so an update is safe to retry or to run in a loop.
  • With Can suggest rather than Can edit, update_document is refused. Propose each change with suggest_edit or bikeshed suggest, quoting the passage as a reader sees it, one paragraph at a time. An empty replacement proposes deleting it.
  • A pending suggestion blocks every new version, from any channel, until a person who can approve decides it.

04

Agent tools

Fifteen tools at /mcp, over streamable HTTP and JSON-RPC 2.0. No session: every request carries its own credential.

ToolWhat it does
list_documentsDocuments you can read, newest first
get_documentA document's metadata and current source; over 200,000 characters it is cut, and says so
publish_documentCreate a document from content you supply
update_documentPublish a new version; identical content is a no-op
get_commentsUnresolved threads on the current version, or on the version you name, each with its quote, its section and every comment, marked with the channel it came through
add_commentStart a thread on a passage of the current version, quoted as a reader sees it, within one paragraph
reply_to_commentAdd a reply to a thread in the current version
suggest_editPropose new text for a passage, for a person to accept or reject
revise_suggestionChange the text of your own suggestion before it is decided; what it said before is kept
withdraw_suggestionTake back your own suggestion before it is decided; its thread stays, marked withdrawn
fork_documentCopy a document you can read into a new private one
get_lineageWhere a document came from and, for its owner, its forks
list_foldersEvery folder you can see, with its full path
create_folderCreate a folder
move_documentMove a document into a folder, or back to the top

The discovery document is at /.well-known/mcp.json. Never send a cut source back through update_document: it would publish the cut.

05

What you can publish

HTML as written, Markdown rendered on the server, or a zip of several files, up to 25 MB.

FileWhat happens
.md .markdownRendered to HTML on the server; get_document returns the Markdown
.html .htmStored as written
.zipSeveral files, with index.html or index.md at the root
  • Put an id on every section. A comment anchors to the nearest element with an id. Without one it anchors to the whole page, and any edit above shifts it. Markdown headings get ids for free.
  • An update keeps the format: a zip replaces every file, and one .md or .html replaces the entry and keeps the files beside it.
  • Markdown is CommonMark with tables, strikethrough and task lists. Mermaid, math, footnotes and front matter show as typed.
  • Scripts run once a person trusts the document: its owner for everyone, any reader for themselves. Each version published through the CLI or MCP sandboxes it again. Images, stylesheets and fonts from other sites load either way.
  • Choose the address with --id, or id in publish_document: lowercase letters, digits and hyphens, up to 60 characters. A taken id gets a few random characters added, so hand back the url the result returns, never one built from the id you asked for.

06

What agents cannot do

Anything that is a decision a person should make on purpose.

  • Share a document, or change who can see it.
  • Set or clear an expiry.
  • Rename or delete a folder.
  • Resolve a thread, or accept or reject a suggestion.
  • Delete a document. Nobody can: a single version can be withdrawn only by whoever runs the deployment.

Everything an agent does carries the channel it came through, cli, mcp or api, taken from its credential rather than claimed. Readers see it as via MCP and the like. A name sent in X-Bikeshed-Agent is shown too, marked as self-reported.

Command reference

Every bikeshed command, in one place.

CommandWhat it does

bikeshed logoutSign out on this computer, revoking a token from browser sign-in
