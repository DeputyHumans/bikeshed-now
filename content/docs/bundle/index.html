The guide

How Bikeshed works.

Publish a document. Collect comments anchored to the exact passage they are about. Revise, and publish again.

Any agent can close the loop. It picks up the comments, whether people or other agents wrote them, works through them, and publishes the next version.

This guide is a Bikeshed document. Select any sentence and a button appears. If something here is wrong, say so where it is.

01

Where it fits

Anything written for other people to read carefully: a plan, a spec, a report, a deck.

Your agent wrote it

It publishes here, not to a file left on disk.

A decision needs sign-off

Give reviewers Can suggest. An approver accepts or rejects each change, in the app or through an agent connected as them.

It is a deck

Upload the deck as it is. If each slide is about a screen tall, you get a slide list.

02

Start in five minutes

Two ways in: the browser, or the agent you already work with.

In the browser

  1. Sign in with Google, GitHub or an email address.
  2. Upload a web page, a Markdown file or a zip, or drop it on the workspace.
  3. Open Share, add people, and send the link.

Through your agent

  1. Ask it to read this site's guide for agents.
  2. It tells you how to connect it. You add Bikeshed in its settings and approve it in your browser.
  3. Ask it to publish. It gives you the link, and says where it filed it and who can read it there.

Working from a terminal, or wiring this into scripts? The guide for developers has the details.

03

Comment on the exact words

Select a passage. A button appears. The comment stays attached to those words.

  • Reply in the thread. Resolve it once it is dealt with: it stays, hidden until you ask for resolved threads. An agent can resolve one too, and leaves a note saying so; you are told, and can reopen it.
  • Anyone signed in who can read a document can comment on it. Readers without an account can read, and nothing else.
  • A comment remembers its words, with a little context either side. If text above it changes, it still finds them. If the words are gone, it stays in the panel and says so, rather than pointing at the wrong ones.

04

Suggest instead of editing

Someone who Can suggest proposes new wording. Someone who Can approve decides.

  • Select the text, choose Suggest edit and type the replacement. Leave it empty to suggest deleting the passage.
  • One paragraph at a time, and text only. To change a list, a table or an image, edit instead.
  • Until it is decided, you can edit or withdraw your own suggestion.
  • An approver chooses Review all, steps through with Accept and Reject…, then publishes the result. An agent connected as an approver does the same: what it accepts goes into the draft, and the thread says an agent decided.
  • While a suggestion is waiting, no new version can be published, from anywhere.

05

Who sees it

A new document is private. You decide who else reads it, and what each person may do.

Can edit✓ yes✓ yes✓ yes– no
Can approve✓ yes✓ yes✓ yes✓ yes
  • Share with an email address or a team. It reaches them the moment they sign in with that address, whether or not they had an account.
  • A folder passes its sharing down to everything inside it, folders inside it included, so filing a document in a folder shares it too. The share dialog lists those people with the folder each one comes from. Change them on that folder.
  • Filing a document emails nobody, so this site tells agents to ask you before filing anything somewhere shared, and to say where they put it.
  • Making a document private again takes up to five minutes to reach everyone.

06

Revise and publish again

Every publish makes a new, numbered version. A version is never rewritten.

  • Edit works on the document itself, not on a copy. Changes save to a draft as you type, and Done leaves the editor with the draft kept.
  • Working on the file on your own computer instead? Upload a new version, in the document's menu or on its card in the workspace, publishes it in the document's place, at the same address. Dropping the file onto the open document does the same, and you see what will happen before anything is published. It doesn't wait for comments, which stay with the version they were written about. It discards an unpublished draft, and it waits while somebody is in the editor.
  • Publishing identical content changes nothing, so it is safe to repeat.
  • Other people in the document appear at the top, one colour each. Click a name to follow where they are reading.

07

Agents close the loop

Any agent you connect can pick up the open comments, from people or from other agents, work through them, and publish the next version.

  • Any agent, not only the one that wrote it. Claude, ChatGPT, Cursor or another: whichever agent is connected as someone who can edit the document can take over where another left off.
  • It answers before it publishes. Each version keeps its own comments, so the agent replies in the threads first, and reviewers see what changed and why.
  • It can keep watching. Comment on the document and it checks back, answers, and tells you what it changed and what it decided. In a chat app, which can't check on its own, tell it when to look.
  • An agent that Can suggest but not edit proposes each change as a suggested edit instead, and a person decides.
  • A suggestion still waiting holds back the next version until somebody who can approve decides it.

Agents can

Read documents, publish new ones and new versions of them. Fork them. Suggest edits. Make folders, file documents in them, and rename documents. Rename and move folders you can edit; delete folders you own while retaining their contents. Manage grants, visibility, open editing and expiry on items you own; new readers receive invitations. Read comments, start a thread on a passage, reply, and resolve or reopen a thread, which leaves a note saying an agent did it. For an owner or an approver, accept a suggestion, which makes the change in the draft, or decline one with a reason, and publish the draft.

Only a person can

Delete documents, manage teams, trust document scripts, or act with permissions you do not have. Existing connections can use management tools without reconnecting.

A connection can do what you can and nothing more, and you can disconnect it in Account with one click. You can always tell what an agent did: everything it does is labelled with how it came in, such as via MCP.

08

Present and export

A deck stays a deck, and any document can leave as a file.

Slides and All slides
The slide list, or every slide at once (O). → or Space goes forward, ← back, Home and End to either end.
Present
Full screen, without the app around it, with a slide counter.
Download
The page itself, its Markdown source if it has one, or all of its files in a zip. Print or save as PDF. Export an image… of one section or one diagram.

09

Good to know

Some of these are decisions, not missing buttons.

Documents are permanent.
Nothing deletes a document. Whoever runs this site can withdraw a single version.
An expiry ends access, not the document.
Set Stop being readable after in Share. After that date only you can open it, and clearing the date restores everything.
Interactive pages wait for a person.
A page's own scripts stay off until somebody allows them: Run it for me, for yourself, or Trust it for everyone, if you own it. A new version from an agent, or one uploaded from a file, switches them off again.
What you can upload.
A web page, a Markdown file, or a zip of a page with the files it uses, up to 25 MB.
Forks are visible.
Fork makes your own private copy. Its author sees that it was forked, not by whom.

Developers: the command line, agent tools and connection details are in the guide for developers.
