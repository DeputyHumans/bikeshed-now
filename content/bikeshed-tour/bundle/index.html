A tour

Bikeshed

Publish a document. Collect comments anchored to the exact passage they are about. Revise, and publish again.

This document is the tour, and it is also a demonstration: it is a self-contained HTML bundle, it carries its own scripts, and it was published the same way anything else here is. Everything it claims is checkable against the source it describes.

Select this sentence and a button appears. That is the whole interaction.

The name

Parkinson's law of triviality: the bike shed is the thing everyone has an opinion about. For a tool whose entire purpose is collecting other people's opinions on a document, the name is the joke and the joke is the product.

The canonical bikeshedding argument is what colour to paint it, which is why the interface has exactly one accent colour and it is one deliberate, arguable choice.

The loop

Four steps, and the third is the one that makes the other three worth doing.

Why anchoring changes the loop

A comment that says "this paragraph overstates the case" is only useful while you both remember which paragraph. Anchored to the text, it is still useful in a month, in a different version, and to somebody who was not in the conversation.

It is also what makes the agent surface worth having: an agent reading feedback gets the passage with the comment, so it does not have to guess.

How an anchor survives an edit

Two selectors, and the pairing is the point. A text quote stores the exact words with a little context either side. A text position stores character offsets.

Quote first, position as the fallback: a position that has drifted points confidently at the wrong words, which is worse than admitting it cannot find them.

Both are scoped to the nearest ancestor with an id. That is what makes them survive at all. Measured against the whole document, every offset shifts when anything above changes, and the quote search has the entire document to get lost in.

Put an id on every section

It is the single most consequential thing you can do to a document you intend people to comment on. 

<section id="rollout-plan">
  <h2>Rollout plan</h2>
  …
</section>

Markdown gets this free: every heading is wrapped in a section whose id is a slug of its text. If you are writing Markdown, just use headings.

What happens without ids

Every highlight anchors to <body>. Add a paragraph at the top and every offset in the document shifts at once, so a comment on the second paragraph starts resolving against the ninth.

And why this example is nested

To demonstrate that rehydration opens every collapsed ancestor, not just the nearest one. Comment on this sentence, reload, and both disclosures open themselves.

Versions are immutable

Publishing mints v1, v2, and so on. A version is never rewritten. Comments belong to the version they were written about, so a revision never orphans them and an old version keeps its discussion.

Publishing identical content is a no-op. The bundle is hashed, and identical bytes produce no new version — which is what makes it safe to publish in a loop, from CI, or after a change you are not sure you made.

The hash, precisely 
files sorted by path
per file: uint32(len path) uint32(len bytes) path bytes
sha256 over the whole stream

The length prefixes make the framing injective: without them, a file called a b containing c and one called a containing  bc would hash identically.

Editing edits the real document

The editor works on the authored markup itself, not on a normalized model of it. A schema editor would decide what a document is allowed to contain, and a deck with inline SVG, a folded tree and a scroll observer is exactly the kind of document such a decision destroys.

While you edit, the document's own scripts are switched off — unconditionally, whatever its trust setting says. Otherwise a script's generated DOM would be saved as static markup while the generator stayed in place, and every later render would append another copy.

Which is why empty containers get outlined

With scripts off, a container a script fills at read time renders as blank space. The editor outlines it and names it, so it reads as "this is filled in later" rather than "the tool lost my content".

The outline is an attribute and a stylesheet, never an inserted node — so nothing it draws can end up inside your document.

Scripts, and who vouches for them

A document renders in an iframe on this origin, which is what lets comments be attached to it without injecting anything into it. That also means an untrusted document's scripts would run somewhere they could read your session, so they do not run at all until somebody vouches for them.

You will have seen the prompt for this document, because it contains scripts and arrived sandboxed. A document with no scripts never prompts — asking about something that would change nothing teaches people to click through the prompt that matters.

Sharing

Share with a person by address, or with a team. Either way it reaches them the moment you share it, whether or not they have an account: the moment they sign in with that address, it is waiting.

What a team grant means

"The design team can read this" is stored as exactly that, and expanded into the six people it names. Adding somebody to the team grants them everything the team holds, immediately — which is the same silence an invitation email exists to break, so one is sent.

Public, unlisted, private

Private is the default and means what it says. Unlisted is readable by anybody holding the link and is not indexed. Public is readable by anybody and is listed.

A folder takes the same three levels, and what they open is everything in it, folders inside it and documents filed later included. Somebody who came in through a folder’s link can read, and nothing else.

Reading without an account never becomes writing without one. A document whose owner turned on open editing widens who may edit to anybody with an account. It never widens to anybody at all.

What a reader without an account can see

The document, and nothing else. Not who else can read it, not who commented, not how long anybody spent reading. Publishing a document must not publish the people who reviewed it.

Other people, live

Open a document somebody else is in and you see where they are: their cursor, their selection, their place in the document, and whether they are typing a reply.

One colour per person, derived from their address rather than assigned, so the same person is the same colour tomorrow and in a different document. The colour is never the only signal — every caret carries a name.

Why only one person can edit at a time

There is no merge engine here, and showing live cursors without a lock would actively invite the one thing last-writer-wins handles badly: two people typing in the same paragraph.

So editing has a single holder. Everybody else watches the draft update, sees the editor's cursor, and can still highlight and comment. Review does not stop because somebody is typing, and "ask to edit" is one tap and is asked once.

Who did what

Every version, comment, highlight and access change records who made it and through what: the browser, the command line, an agent. The channel is derived from the credential presented, so it cannot be claimed.

A client may also name itself and its model. Those are stored and shown as self-reported, with no badge implying they were checked — because they were not, and a badge that implies verification it does not have is worse than no badge at all.

And why agent reads are counted separately

An agent fetching a document forty times would turn "how many people read this, and for how long" into noise — and reading time is not a concept that applies to a machine fetch at all. Automated reads get their own counter and never touch the human numbers.

Agents publish here too

A personal access token, six MCP tools, and a command-line client. A token carries exactly its owner's permissions: it can see what they can see and nothing more, and there are no service accounts to widen that. 

bikeshed publish proposal.md --title "Storage migration"
bikeshed comments storage-migration
bikeshed update storage-migration proposal.md

The tool that earns the whole surface is get_comments: it returns each comment with the passage it is anchored to, so an agent can revise without fetching the document and diffing it.

Taking it with you

Print or save as PDF, export a section as PNG, pull a diagram out as SVG, or download the document as the file it is. A Markdown document gives you back the Markdown.

An owner can set a marking — a corner label and a per-page footer — that is stamped on every export. It is their policy, resolved when they published, not the exporter's preference.

Why the marking cannot be styled away

The stamp's styles are set inline with !important, which outranks any stylesheet rule a document could carry, and the print frame runs with no scripts, so a document has nothing with which to change them. Every hiding trick is covered — including making the box visible but its text invisible, which is the half people forget.

What this is not

Stated plainly, because a list of decisions is more useful than a list of features:

  • Not a word processor. It edits documents you authored elsewhere, in the markup you authored them in.
  • Not collaborative editing. Shared awareness, yes. A merge engine, no — and a single-writer lock is what makes that honest.
  • Not a wiki. No search index, no cross-linking, no hierarchy beyond folders.
  • Not an analytics product. Reading time for the owner of a document; nothing that identifies an anonymous reader, ever.
  • Not deletable. Documents are permanent by design. A single version can be withdrawn by whoever runs the deployment, through a guarded tool with seven refusals.

If something here seems wrong, highlight it and say so. That is the entire product, and this document is the obvious place to start.
